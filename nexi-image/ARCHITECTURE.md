# Architecture

## Native tier profiles

`nexi_image.tiers` adds three explicit profiles described in `TIERS.md` and pinned
by `manifests/{small,medium,best}.json`. It reuses immutable downloads and the
existing native runtime pin; inference never downloads. Small converts BK's
sparse Diffusers U-Net to the native original-SD tensor layout using
`convert_bk`; medium streams quantization of the official four-step Lightning
checkpoint. Derived artifacts have local build receipts checked at inference.
Best uses published quantized Klein/Qwen weights and the full encoder/small
decoder. All native processes use disk-backed parameters, flash attention,
CPU-only execution, explicit seeds and tiled VAE processing.

Small/medium editing uses img2img and optional native latent masks; best sends
actual image references to FLUX.2's instruction-editing conditioner. Aspect-fit
staging and EXIF normalization are explicit. Optional final compositing preserves
unselected RGB pixels exactly on the staged canvas; for best this is an output
operation, not trained mask conditioning. Native output is staged, verified and
atomically moved; failed inference cannot reuse an old image as evidence.

`wait4` captures complete child peak RSS; `/proc` sampling records live parent
and child RSS every 50 ms. Summing the parent and child's individual peaks gives
a conservative upper bound, not an exactly simultaneous peak. Neither metric
includes OS/page-cache/other-app requirements. The wrapper currently measures on
Linux only; alternative native platforms have not been verified.

## Original isolated Diffusers route

## Original baseline: BK-SDM-Tiny / TAESD

```text
explicit download -> revision/size/SHA-256 manifest -> local model directory
                         |
generate parent (stdlib, no tensor framework; verify all hashes)
  -> fresh encode process: tokenizer + CLIP -> embeddings.pt -> exit
  -> fresh denoise process: BK U-Net + DDIM + optional LoRA -> latents.pt -> exit
  -> fresh decode process: TAESD -> PNG -> exit
  -> JSON provenance report; remove temporary tensors
```

The encode process produces negative/unconditional and positive embeddings.
Seeded CPU noise supplies the initial latent. Classifier-free guidance runs the
negative/positive branches sequentially by default; `--batched-guidance` uses
a batch of two for speed at higher peak memory. DDIM uses `eta=0`. TAESD consumes the
result with **TAESD's own scaling factor (1.0)**, not the original VAE's 0.18215.
These are genuine pretrained text-conditioned networks; no fixed image selection
or random tiny network is involved.

Worker isolation releases component weights and framework allocations when each
process exits. It does not eliminate framework imports, attention activations,
temporary copies or OS memory. Denoising was the largest resident component.
The parent remains alive, so maximum worker RSS is **not** total application or
device RAM. Do not sum sequential worker peaks either.

`driver.generate` is the synchronous API; `worker` is internal. Model files are
local-only and hash-verified each generation; this costs time and warms the OS
page cache. Hash/download manifests live beside the package. Only setup and
`download` require network. No remote code is trusted or executed by model
loading. Model and adapter tensors use safetensors. Temporary inter-process
PyTorch tensor files are generated by our own workers in a private temporary
directory and loaded with `weights_only=True`.

Model revisions:

| Component | Upstream revision |
|---|---|
| BK-SDM-Tiny | `0364108e53b7f7f4d2585e817a0b7a83dc261cfa` |
| TAESD | `614f76814bbe30edbe2e627ace1c2234c81a2c0e` |

The download helper verifies each completed file before atomic replacement;
partial downloads use distinct names so concurrent attempts cannot delete one
another's temporary file. Downloads are not resumable. An interrupted/corrupt
file is retried on the next explicit download, never silently during inference.

## Adaptation

The training command validates a local captioned-image JSONL. Separate processes
encode captions and images with the original BK VAE. The VAE's training latents
use its original scaling factor. Text encoder/VAE remain frozen. The training
process loads the BK U-Net in FP32, freezes its base parameters, and attaches
PEFT LoRA matrices to `to_q`, `to_k`, `to_v` and `to_out.0`. It uses batch one,
gradient checkpointing, DDPM noise-prediction MSE, AdamW and gradient clipping.
Precomputed tensors are held in memory: large datasets are **not** streaming.

Training saves only trainable tensors plus provenance JSON. Inference loads the
adapter into the same BK attention layers. This is a working optimizer route,
not a validated style/subject finetune. The smoke test uses one synthetic image
only to exercise training and loading. For useful adaptation choose a licensed
dataset, validation prompts and sufficient training; verify quality separately.

## Native experimental profile

`native.generate` starts a fresh pinned `stable-diffusion.cpp` executable. Its
model is **SD1.5 Q4_0**, not the BK model. CLIP and the VAE stored in that GGUF
are FP16; the active decoder is full TAESD. Default standard generation uses
ten Euler ancestral steps and guidance 7. Optional `--profile lcm` applies the
SD1.5 LCM adapter, four LCM steps and guidance 1. CPU flash attention reduces workspace; disk parameter
placement releases/reloads tensors instead of keeping all weights resident.

The wrapper checks the runtime's reported commit prefix, records the binary
SHA-256, invokes the executable with an argument list (no shell), captures logs
and measures the child via `os.wait4`. Output is staged in a unique directory
and atomically installed only on success, preventing stale PNGs from being
reported as a new generation. The native build is outside the repository and
none of its source is modified. The pinned runtime needs full TAESD metadata,
including encoder tensors even in text-to-image use.

Disk-backed parameters reduce residency, **not model storage**. Published native
memory estimates exclude our exact CPU/build/configuration. Our measurements
still exceeded 1 GB. Ten-step standard output was recognisable; four-step LCM
outputs had strong artifacts. This route is an honest experiment, not a
lower-RAM guarantee or a production quality option.

## Not implemented

No mobile packaging, GUI, HTTP server, safety checker, prompt moderation,
ControlNet/dedicated inpainting finetune, quantized BK training, image upscaling,
or cloud fallback.
No multi-device benchmark, FID/CLIP evaluation, or useful trained adapter is
claimed. No upstream weights have been renamed as a NEXI finetune.
